## 역할
### 1) 데이터셋 담당

울산 채용공고 수집·구조화 (2번 기능)
울산 정착지원 정보 수집: 주거(청년주택, 이주지원금), 교통, 교육 프로그램 등 (5번 기능) — 이것도 별도 정적 데이터셋이 필요함, 울산시청/울산일자리재단/울산도시공사 자료 참고

### 2) 매칭 알고리즘 담당

3번 기능인 매칭률 계산 로직 (전공/경험/기술/근무조건 적합도를 어떻게 수치화·가중합할지 설계)
여기가 심사에서 제일 "기술력" 보이는 부분이라 별도로 빼두는 게 좋음 — 단순 키워드 매칭이 아니라 "실제 담당업무 vs 사용자 경험"을 임베딩 유사도로 비교하는 방식이면 더 설득력 있음

### 3) AI 프롬프트/설명생성 담당

4번 기능 (추천 이유 설명, "내가 놓치고 있던 직무" 발견 로직) — OpenAI API로 매칭 근거를 자연어로 풀어주는 프롬프트 설계
1번(이력서 정보 추출) 프롬프트도 이 팀이 이어서 관리하면 일관성 있음

### 4) 프론트엔드/UX 담당

프로필 입력 화면, 매칭 결과 카드(매칭률 %, 세부 점수 바), 공고 상세, 정착정보 연결 화면
매칭 점수를 얼마나 직관적으로 시각화하느냐가 데모 임팩트에 크게 좌우됨

## 공통 규칙
main에 직접 push하지 않습니다.
작업 전 git pull 후 자신의 브랜치를 만듭니다.
공통 타입이나 package.json을 바꾸기 전에 팀에 알립니다.
PR 하나에는 한 기능만 담습니다.
.env.local과 API 키를 커밋하지 않습니다.
완료는 내 컴퓨터가 아니라 PR 미리보기 또는 팀원 환경에서도 작동하는 상태입니다.
